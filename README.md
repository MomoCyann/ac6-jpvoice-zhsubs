# 皇牌空战 6：日文语音 + 中文字幕（PC 重编译版移植方案）

> 适用对象：在 PC 上用 **ac6_recomp / rexglue** 跑 Xbox 360《Ace Combat 6》，并且手上有一份**汉化组制作的 assets 包**（汉化只覆盖英文字幕）的玩家。
> 目标：语言选「日本語」时，**语音是日语、字幕是中文**。

一句话原理：**游戏只有一个语言开关，它同时决定语音包和文本资源。汉化组只改了"英文槽"，所以我们把英文槽里的中文资源，复制进"日文槽"。**

> **只想装补丁、不想看原理？** 看 **[给玩家的使用说明（小白版）](docs/USER-GUIDE.md)**，或者直接用补丁包里附带的 `使用说明.txt`。
> 本 README 面向的是想**自己动手改、或者想二次开发**的人。

## 1. 问题本质

游戏内部只有一个「语言」概念，它同时驱动两件事：

```
language ─┬─> 选哪个 voicepack（语音包，XMA 音频）
          └─> 选哪个文本表 / 哪套字幕资源
```

而汉化组只做了**一件事**：把「英文」这一套资源里的文本和字形换成了中文。
所以：

- 选英文 → 中文文本，但**语音是英语**（不是你要的）
- 选日文 → 日语语音，但**文本是原版日文**

社区里常见的"改一下 language 配置"、"把 voicepack_eng 硬链接到日文包"都行不通，原因见 [5.1](#51-为什么硬链接-voicepack-不行)。

### 1.1 为什么是「搬字幕」，而不是「搬语音」

这是整个项目最重要的一次取舍，值得单独说清楚。

既然两边只能留一个，为什么选"把中文搬到日文槽"，而不是"把日语语音搬到中文那套去"？

**因为这两种资源的"自洽程度"完全不同。**

**字幕/文本是整套的。** 一套语言资源里包含：文本表、字体、汉字字模图集、排版表，全都装在一个语言槽里，互相配套。整块复制过去，游戏读日文槽时自然拿到一整套中文资源，不需要改任何索引。语音完全不用碰。

**语音是散装的。** `voicepack_eng.bin` / `voicepack_jpn.bin` 里面只有一段接一段的 RIFF/XMA 音频，**没有任何索引结构**。哪句台词在第几个字节，记在外部的偏移表里，而且**每种语言各存一份**。所以：

- 把日语包改名成 `voicepack_eng.bin` → 偏移表还是英语那一份，日语每句长度都不同 → 每一句的起点全部错位 → 静音、从句子中间开始播、爆音，甚至卡死
- 这种错位**不会报错**，游戏只会安静地放错东西，排查成本极高

再有三条现实理由：

| 维度 | 搬字幕 | 搬语音 |
|---|---|---|
| 有没有可搬的成品 | 汉化组做了中文文本，整块可用 | 没有"中文语音"，只能搬日语原声 |
| 风险 | 字幕错位只是显示难看，游戏照常进行 | 偏移错一位 = 整关语音报废，且难定位 |
| 回滚成本 | 只改 `DATA.TBL` 里 3 个数字，原字节不动，还原 = 换回 15 KB 的 TBL | 要重打包几百 MB 音频流，并同步外部偏移表 |

**一句话：字幕是「整套书」，搬过去就能读；语音是「散页 + 目录」，书搬了，目录换不了。**

而且必须强调：游戏里**中文只存在于文本那一套**。汉化组汉化的是文本和字体，语音从来不在汉化的范围内。所以"日语语音 + 中文字幕"这个组合，物理上只能通过"把中文文本搬进日语那一套"来实现——这不是偷懒，是唯一可行的那条路。

## 2. 原理

分两层：**运行时层**决定"读哪一套"，**资源层**决定"那一套里装的是什么"。

### 2.1 运行时层：把两个开关拆开

游戏通过 `XGetLanguage()` 和 `XGetGameRegion()` 两个接口取区域/语言信息（见 `rexglue-sdk` 的 `xam_info.cpp`）。这两个值在重编译版里由 `ac6recomp.toml` 控制：

```toml
game_region  = 511   # 让日语语音包出现在可选列表里
user_language = 1    # 1 = 日本語（决定读哪套文本资源）
user_country  = 103  # 与语言配套的国家码
```

改完这一步，你已经能选「日语语音 + 日语字幕」。**但字幕还是日文**——因为日文槽里装的确实是日文。要解决的是下一层。

### 2.2 资源层：把中文搬进日文槽

游戏资源打包在两个文件里：

```
assets/
├── DATA.TBL      索引表：8 字节头 + N 条 × 16 字节（大端）
│                每条 = { flags, offset, comp_size, uncomp_size }
├── DATA00.PAC    裸数据堆 A（2.4 GB）
└── DATA01.PAC    裸数据堆 B（686 MB）
```

- **归属**：`flags & 0x01000000` 为 0 → 在 `DATA00.PAC`；为 1 → 在 `DATA01.PAC`
- **压缩**：`flags & 0x00010000` 表示使用 "mode-1" 压缩 = `raw deflate(-15)` 后再和 **π 的十六进制小数**做 XOR 垫
- **容器**：解压后是 `FHM ` 容器，`0x10` 处是子块数量，`0x14` 起是偏移表，随后是尺寸表

真正要动的结构长这样（以过场包为例）：

```
package (FHM)
└── chunk0 (FHM)
    └── chunk2  ← 语言容器 FHM[7]
        ├── [0] 日本語  ┐ FHM[CAPT, 排版表, 图集]
        ├── [1] English ┘ ← 汉化组把这里换成了中文
        ├── [2] Français
        └── ...
```

**操作就是把 `[1]` 的内容复制到 `[0]`。** 改完之后，游戏选日语 → 读 `[0]` → 拿到中文。

### 2.3 写入策略：只追加，不覆盖

我们的脚本**从不修改已有字节**，而是把新构建的包压缩后**追加到 PAC 文件末尾**，然后只改 `DATA.TBL` 里那一条的 `offset / comp_size / uncomp_size`。

好处：
1. 回滚只需要还原 `DATA.TBL`（几 KB），不用还原 2.4 GB
2. 中途出错不会破坏原始数据
3. 可以反复迭代

代价：PAC 会越来越大。本项目做完后 `DATA00.PAC` 从 2.41 GB 涨到 2.44 GB。

## 4. 操作流程

### Step 0 — 备份（不做这步别往下看）

```bash
cd "你的游戏目录/assets"
cp DATA.TBL DATA.TBL.bak-original
```

`DATA00.PAC` / `DATA01.PAC` 不需要备份（脚本只追加），但如果你要重来，把整个 `assets` 目录复制一份最省心。

**同时记录原始文件大小**，出问题时能对得上：

```bash
ls -l DATA00.PAC DATA01.PAC DATA.TBL
```

### Step 1 — 改运行时配置

编辑游戏根目录的 `ac6recomp.toml`：

```toml
game_region  = 511
user_language = 1
user_country  = 103
```

启动游戏，进设置确认「语音」里能选到**日语**。这一步不成功，后面的资源改动都没有意义。

### Step 2 — 准备脚本

```bash
git clone <this-repo>
cd <this-repo>/scripts
python -m pip install numpy
```

先验证脚本能正确解析你的资源：

```bash
python apply.py list --dir "你的游戏目录/assets" | head
```

应该输出类似：

```
#1    flags=00010000 off=3391488      comp=10584695  raw=21499904  pac=DATA00.PAC
```

如果全是 `unreadable` 或直接报错，说明版本不匹配，**停下来**，先去 [docs/FORMAT.md](docs/FORMAT.md) 核对结构。

### Step 3 — 先空跑，看它准备做什么

```bash
python apply.py all --dir "你的游戏目录/assets" --dry-run
```

`--dry-run` **不写任何文件**，只打印计划。确认输出里的条目号、槽位路径符合预期。

### Step 4 — 正式执行

```bash
python apply.py all --dir "你的游戏目录/assets"
```

脚本会自动备份 `DATA.TBL`（文件名带时间戳），然后依次做三件事：

| 阶段 | 内容 | 涉及条目 |
|---|---|---|
| `task` | 任务包：字体 `chunk4 ← chunk5`，语言容器 `slot0 ← slot1` | #9 ~ #23 |
| `cg` | 章节 CG 包：语言容器 `slot0 ← slot1`（**实测对 CG 字幕无效**，见第 7 节） | #474, #477 … #529（18 个） |
| `dup` | **汉化漏掉的副本包**：从正本取中文槽，写入副本的 slot0 和 slot1 | #103, #109, #111, #115, #117 |

> `dup` 这一步是最容易漏的。汉化组只改了正本（#9/#15/#17/#21/#23），而游戏在某些场景读的是**副本**（#103/#109/#111/#115/#117），副本至今还是原版日文。**不处理这一步，任务 1 / 7 / 9 / 13 / 15 的过场会是日文。**

### Step 5 — 审计

```bash
# 只做一致性检查
python audit.py --dir "你的游戏目录/assets"

# 带原版基线（推荐）
python audit.py --dir "你的游戏目录/assets" \
                --iso "X:/path/to/game.iso" \
                --iso-tbl "DATA.TBL.orig"
```

期望输出：

```
language containers: 42, slot0==slot1: 42, mismatched: 0
slots still identical to stock Japanese: 0

VERDICT: PASS
```

- `mismatched > 0` → 有容器没统一，重跑 Step 4
- `still identical to stock Japanese > 0` → 有副本没被发现，把条目号记下来，用 `apply.py` 手动加进去

### Step 6 — 进游戏验证

选「日本語音声 + 日本語字幕」，依次看：

1. 任务简报（briefing）的字幕
2. 任务中队友/指挥的**无线电字幕**
3. 任务 1 开场过场（`dd01_01a`）
4. 任务 1 结束过场（`dd01_02a`）
5. 任务 7 / 9 / 13 / 15 的过场（副本包覆盖的）
6. 任意一段章节 CG（`ed01` 等）

前 5 项应该是中文——**第 1～4 项已由玩家实测确认通过**。第 6 项**确认仍是日文**，原因与排查方向见第 7 节。

## 5. 注意事项（踩过的坑）

这一节比上面所有步骤都值钱。每一条都是实际踩出来的。

### 5.1 为什么硬链接 voicepack 不行

有人会想：把 `voicepack_eng` 指向日文数据不就行了？
**不行。** 语音包内部只有连续的 RIFF/XMA 流，**没有任何索引**；每句话的偏移表存在**外部**，并且是**按语言分别存**的。换个包名，偏移表对不上，游戏要么静音要么崩溃。必须走资源层。

完整推理见 [1.1](#11-为什么是搬字幕而不是搬语音)。

### 5.2 `flags` 不能全信，读的时候两个 PAC 都要试

初版脚本按 `flags & 0x01000000` 决定去哪个 PAC 读，结果 **797 条解压错位**。
正确做法：**两个 PAC 都试一遍，用 `uncomp_size` 校验长度**，长度对上才算成功。
写的时候才用 `flags` 判断归属（而且要 `assert`）。

### 5.3 压缩垫必须按"条目索引"算，不是按文件

π 的 XOR 垫取的是 `W[2*(idx % 256) + 1]` 和 `W[2*(idx % 256) + 2]`，`idx` 是**这条记录在 DATA.TBL 里的序号**。
算错索引 → 压缩数据完全无法解压 → 游戏读不到资源 → 黑屏或崩溃。

### 5.4 必须以汉化包为基底，不能以原版为基底

第一版脚本用原版 ISO 的包当基底、只把中文槽塞进去，结果**中文全丢**。
原因：汉化组不只改了字幕槽，还改了字体、字号、排版表。必须以**汉化后的包**为起点，只做"槽位复制"。

### 5.5 正本和副本都要处理

游戏里同一个过场的资源存在**两份**（正本 + 副本），汉化组只改了正本。
判断方法：把副本的槽哈希和原版 ISO 的槽哈希对比，**完全相同**就说明没被汉化过。
本项目里是 #103/#109/#111/#115/#117 对应 #9/#15/#17/#21/#23。

### 5.6 副本的两个槽都要写

只写 `slot0` 时，实测 `slot1` 仍是英文（原版资源）。虽然理论上游戏只读 `slot0`，但为了不依赖这个假设，**两个槽都写中文**最保险。

### 5.7 Windows 路径不要写 `/f/`

Python 在 Windows 上会把 `/f/foo` 解释成 `C:\f\foo`。脚本里一律用 `F:/foo` 或 `r"F:\foo"`。

### 5.8 追加式写入不是幂等的

每跑一次，PAC 就长大一点。脚本里对"已经一致"的槽做了跳过判断，但如果你手动改过、或者中途中断，**重跑前先看 `--dry-run` 输出**，确认没有重复追加。

### 5.9 语言槽索引：0 = 日文，1 = 英文/中文

7 语言容器的顺序是固定的：

```
[0] 日本語   [1] English(汉化后=中文)   [2] Français
[3] Italiano [4] Deutsch   [5] Español   [6] ...
```

不要凭"看起来像中文"去猜槽位，用哈希比对。

### 5.10 字幕不是文本，是烘进纹理的字形

想改翻译？**做不到"改几个字"这么简单。**
整个资源库里**没有任何中文明文**（UTF-8 / GBK / UTF-16LE / UTF-16BE 全扫过，0 命中）。字幕实际是：

```
CAPT 块 → 排版表 + 图集 FHM → 字形纹理（NTXR, DXT5）
```

中日文图集是 **2048×256**，其他语言只有 256×256 —— 说明汉字是**逐字烘进纹理**的。改一句翻译 = 重画字形位图 + 重新编码 DXT5 + 处理 Xbox 360 的 tiled 布局。成本极高，不建议。

### 5.11 别碰全局字体包

`#467` ~ `#472` 是字体资源（CAPT 表为空，没有字幕条目）。汉化组已经换过 `#467` 的中文大图集，**不要重复处理**，否则可能出现方块字或字重错乱。

## 6. 回滚

所有改动都在 `DATA.TBL` 里，PAC 只是多了尾部数据（不影响读取）。

```bash
cd "你的游戏目录/assets"
cp DATA.TBL.bak-jpzh-<时间戳> DATA.TBL
```

或者用最早的备份：

```bash
cp DATA.TBL.bak-original DATA.TBL
```

回滚后 PAC 里残留的追加数据是**死数据**，不影响游戏，也不会被读取。想彻底清理，只能重新解包/重打包整个 PAC（不推荐）。

## 7. 尚未解决的问题

### CG 过场字幕仍然是日文（已实测确认）

**现象**：章节 CG（`ed00_01` 开场动画、`ed01` ~ `ed15`）字幕仍是日文。

**这条是实测结论，不是推测**：把 18 个 CG 包（`#474` ~ `#529`）的语言容器全部统一成中文之后，玩家进游戏播放开场 CG，**画面上一个字都没变**——仍然完全是日文。同时，同一份补丁下任务一的简报、无线电、任务内过场字幕全部变成中文且显示正常。

也就是说：**`task` 那条路径是通的，`cg` 这条路径是死的。** 改动对 CG 显示零影响，说明这 18 个包的 CAPT 槽根本不是 CG 字幕的画面的来源。

**已经排除的可能**：

1. `moviepack.bin`（698 MB，ASF/WMV 视频包）与**原版 ISO 逐字节一致**（7 个采样点全部 SAME），汉化组没动过视频
2. 视频内**没有任何字幕流**：`Script` / `Caption` / `Subtitle` 标记出现次数均为 0
3. `demopack_*.bin` 是 XMA 音频，`bgmpack.bin` 是背景音乐，与字幕无关
4. 写入位置错误：CG 包 `flags = 0x01010000`，确认写入的是 `DATA01.PAC`，索引偏移也对得上——不是"写错了文件所以静默失效"这种低级错误

**这段影片已经定位到了（2026-11-13 补充）**：

`moviepack.bin` 里正好装着 **4 段影片**，起始偏移固定：

| 段 | 起始偏移 | 槽位大小 | 时长 | 数据包数 | 标称文件大小 |
|---|---|---|---|---|---|
| 0 | 0 | 164,657,152 | 118.07 s | 3,724 | 59,590,129 |
| 1 | 164,657,152 | 164,644,864 | 118.07 s | 3,724 | 59,590,129 |
| 2 | 329,302,016 | 183,547,904 | 118.07 s | 3,724 | 59,590,129 |
| 3 | 512,849,920 | 185,567,232 | 118.07 s | 3,724 | 59,590,129 |

四段的**时长、包数、标称大小完全一致，只有槽位长度不同**——这不是四段不同的过场，而是**同一部影片的 4 个语言版本**（约 2 分钟，正片头 / 带 staff credits 的那段）。文字和名单是**直接烧进画面像素**的，所以既没有字幕流，也不经过 CAPT 资源。

结论：**玩家看到的那段"像动漫 OP 一样、带制作人员名单"的动画，就是这里面的日文版。** 汉化组一个字节都没改过它，所以在汉化版里它本来就一直是日文，不是我们的补丁造成的。

要让它变中文，**唯一路径是重制视频**：解码出画面 → 贴中文字幕 → 重新编码 → 按原槽位大小回填。工程量很大，且 `moviepack.bin` 是独立文件、不经过 `DATA.TBL` 索引，回填时还必须保持 4 段的偏移不变。目前不做。

**关键疑点**：

把 `#474` ~ `#529` 这些包的顶层块和原版 ISO 逐块比对，**汉化组一个字节都没改**。
进一步解析 CAPT 结构时发现，这些包的**字幕索引表全部为空**（0 条有效条目），它们更像是**字体/字形容器**而不是字幕文本容器。

**结论**：CG 字幕的真实来源**尚未定位**。`apply.py cg` 这个模式目前的实际作用只是替换了字体，对 CG 字幕没有效果——留着它是为了保持资源一致，不要指望它能解决问题。

### 这件事就留在这里，不再投入

汉化组**很可能是做过**这段的（毕竟汉化版是完整发行物，不该偏偏漏掉片头），但现有手段确实够不着：画面里的文字不在任何可替换的资源槽里，而视频本身又是逐字节等于原版的。**目前没有能落地的解法，所以停在这里。**

判断依据也很简单：这段不影响任何主线流程——不看不影响理解剧情，跳过不影响进度。为一个 2 分钟的片头去重制整段视频（解码 → 贴字幕 → 重编码 → 按原偏移回填 4 段、保持槽位大小不变），投入产出完全不划算。

**留下的线索**（记录在此，供将来有兴趣的人参考，但**不建议**再投入）：

1. 决定性实验：用**原版 ISO + 原版 assets** 播同一段，与汉化版对比，能定性"汉化组到底做没做"
2. `#878` ~ `#924`：汉化组改过、但还没分析过的 47 个条目（体积 4288 字节左右、熵接近 8），有可能是字幕索引/配置
3. `#500`、`#618`、`#683`、`#779`：同样被改过，单条目，用途未知
4. 运行时 hook 资源加载函数，记录播放 `ed01` 时读了哪些条目号（需要能编译 `rexglue`）
5. 游戏目录下是否有独立的字幕配置文件（`.srt` / `.txt` / `.ini`）

如果你解决了这一段，欢迎提 PR——但请先确定你有办法**验证**改动生效，否则就是重复本项目已经踩过的坑。
