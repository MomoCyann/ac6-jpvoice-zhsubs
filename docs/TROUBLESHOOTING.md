# 排错手册

症状 → 可能原因 → 处理。

---

## 1. 启动 / 运行问题

### 黑屏、卡在启动画面、进入任务即崩溃

**最可能**：`DATA.TBL` 里某条记录的 `offset / comp_size / uncomp_size` 与实际数据对不上。

**排查**：

```bash
python apply.py list --dir "你的assets目录" | head -20
```

如果输出正常说明 TBL 结构没坏，问题在数据本身。

**处理**：

```bash
cp DATA.TBL.bak-jpzh-<时间戳> DATA.TBL
```

回滚到上一个状态。如果回滚后仍然崩溃，说明 PAC 被外部工具改过，需要重新获取干净的 assets。

> ⚠️ 追加式写入不会破坏原有数据，所以**只要 TBL 能回滚，就一定能恢复**。这是这套方案最重要的一条保险。

---

### 游戏能启动，但资源加载失败 / 贴图缺失 / 音频断续

**原因 A**：压缩时 π 垫索引算错（用了偏移而不是记录号）。

**原因 B**：非 ASCII 路径导致脚本读写错了文件。

**排查**：确认 `DATA00.PAC` / `DATA01.PAC` 的文件大小变化是否符合预期（本项目从 2.41 GB → 2.44 GB）。如果暴涨几十 GB，说明重复追加了。

---

## 2. 文字显示问题

### 字幕/菜单变成方块或乱码

**原因**：字体资源和文本资源的版本不匹配。常见于只替换了文本槽但没替换字体槽，或者反过来。

**处理**：

1. 确认 `#467`~`#472` 是汉化组的版本（不要用原版覆盖）
2. 确认任务包的 `chunk4` 已换成 `chunk5`（日文字体 ← 含汉字字形的字体）
3. 全部重来：还原 `DATA.TBL.bak-original`，重新跑 `apply.py all`

---

### 部分场景仍是日文

**排查顺序**：

1. 先确认是**哪一段**。让用户说明：哪一关、过场前发生了什么、是实时渲染还是预录 CG
2. 实时过场（`dd`）→ 可能是副本包漏了
3. 预录 CG（`ed`）→ 见 [README §7](../README.md#7-尚未解决的问题)，目前未解决

**定位方法**：

```bash
# 检查所有语言容器是否都统一了
python audit.py --dir "你的assets目录"
```

如果 `mismatched > 0`，看输出的条目号，用 `apply.py` 单独处理。

**找副本包的方法**：把可疑包的每个语言槽 md5 和原版 ISO 对应包比对。**完全相同 = 没被汉化过**。

---

### 字幕能显示中文，但位置/换行不对

**原因**：排版表（语言块的 chunk1，`47 × 16` 字节）还是日文的，而字宽变了。

**现状**：这个问题**目前无法修复**。排版表的字段含义还没有完全逆向出来（只知道未使用项填 `0xFF`）。

**影响**：一般不影响阅读，只是断行位置可能偏早或偏晚。

---

## 3. 语音问题

### 没有日语语音选项

**原因**：`game_region` 不是 `511`。

**处理**：`ac6recomp.toml` 改成

```toml
game_region = 511
```

### 选了日语，但语音是英语

**原因**：`user_language` 没设成 `1`，或者游戏读的是别的配置。

**排查**：

```toml
user_language = 1
user_country  = 103
```

### 试过"硬链接日文语音包"，结果没声音

**这是必然的。** 语音包内部没有索引，偏移表在外部按语言存放。见 [README §5.1](../README.md#51-为什么硬链接-voicepack-不行)。

**处理**：删掉硬链接，恢复原文件，走资源层方案。

## 4. 脚本运行问题

### `ModuleNotFoundError: No module named 'numpy'`

```bash
python -m pip install numpy
```

### 路径被解析成 `C:\f\...`

**原因**：Windows 上 Python 把 `/f/foo` 当成 `C:\f\foo`。

**处理**：用 `F:/foo` 或 `r"F:\foo"`，**不要用** `/f/foo`。

### `assert len(data) == uncomp_size` 失败

**原因**：压缩垫索引错了，或者读到的是另一个 PAC 的越界数据。

**处理**：检查 `decode_record()` 传入的 `idx` 是不是**记录号**。这是最容易错的地方。

### 跑完 PAC 体积暴涨

**原因**：重复运行导致反复追加。

**处理**：

1. 先 `--dry-run` 确认输出是 `already ok` / `unchanged`
2. 如果大量 `would update`，说明槽位哈希不一致，先搞清楚为什么
3. 体积已经涨了：还原 `DATA.TBL` 回到旧偏移即可（多余的追加数据变成死数据，不影响运行）

### `audit.py` 报 `REVIEW` 但看不出问题

看输出的分类：

- `mismatched: N` → 语言容器槽位没统一，重跑 `apply.py all`
- `caption containers WITHOUT a language wrapper` → 可能是真正漏掉的裸字幕容器，**也可能**是字体包。看 `entries=` 是否为 0：0 就是字体包，忽略
- `still identical to stock Japanese` → 有副本没处理

## 5. 版本不匹配

### 换了一个 ISO dump，`--iso` 参数报错

**原因**：ISO 里两个 PAC 的偏移是硬编码的（`0x06197F800` / `0x154E3A000`），不同 dump 不一样。

**处理**：按 [FORMAT §8](FORMAT.md#8-iso-定位取原版基线用) 重新推导偏移，改 `audit.py` 顶部的常量。

### 换了汉化组的版本（更新了汉化包）

**处理**：

1. 检查条目数是否还是 926
2. 重跑 `audit.py`，看语言容器数量是否还是 42
3. 如果结构变了，先按 [FORMAT](FORMAT.md) 核对，不要直接跑 `apply.py`

### 游戏本体更新了（ac6_recomp 换了版本）

一般不影响资源格式，但配置项可能变。检查 `ac6recomp.toml` 里 `user_language` / `game_region` 是否还在。

---

## 6. 想完全重来

```bash
cd "你的assets目录"

# 1) 还原索引（关键）
cp DATA.TBL.bak-original DATA.TBL

# 2) PAC 不用动：所有追加数据都变成死数据，不会被读取

# 3) 重新打补丁
python apply.py all --dir "."
```

如果连 PAC 都想清理成原始大小，只能从原版 ISO 重新解包，**不推荐**（耗时长、容易出错）。
