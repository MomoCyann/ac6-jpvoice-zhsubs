# 工作日志

> 这是一份**过程记录**，不是教程。教程看 [README](../README.md)，格式细节看 [FORMAT](FORMAT.md)。
> 记录的目的是：让接手的人（或 AI Agent）知道**哪些路已经走过、为什么走不通**，不要在同一个坑里再摔一次。

时间跨度：单日完成，分 11 个阶段。

---

## 阶段 0 — 需求与约束

**需求**：游戏用 ac6_recomp 跑，assets 来自汉化组。要「日文语音 + 中文字幕」。

**约束**：

- 汉化只覆盖英文字幕槽
- 游戏只有一个 language 开关，同时决定语音包和文本资源
- 不能重新制作汉化，只能用现有资源做迁移

**初始错误假设**：以为这是"改配置"或"换文件"级别的活。
实际上需要逆向 Xbox 360 的资源容器格式。这个误判导致了后面两个阶段的无效工作。

---

## 阶段 1 — 配置层：拆开两个开关

**做法**：读 `rexglue` 源码，找到 `xam_info.cpp` 里的 `XGetLanguage()` 和 `XGetGameRegion()`。
这两个接口分别读配置里的 `user_language` 和 `game_region`。

**结果**：

```toml
game_region  = 511
user_language = 1
user_country  = 103
```

设置后，游戏里能选到**日语**了，语音也是日语。

**但**：字幕还是日文。因为 `user_language = 1` 就是让游戏读"日文那一套资源"，而那套资源本来就是日文。

**结论**：配置层只能解决"用哪套"，解决不了"那套里装的是什么"。
→ 必须动资源层。

---

## 阶段 2 — 语音包硬链接（失败）

**假设**：语言开关决定"读哪个 voicepack 文件"，那只要让 `voicepack_eng` 指向日文数据，不就能"英文语言 + 日文语音"了吗？

**做法**：用 NTFS 硬链接把英文 voicepack 的文件名指向日文包的数据。

**结果**：进游戏，语音没变，或者直接异常。

**原因**（后来才搞清）：

- 语音包内部只有连续的 RIFF / XMA 流，**没有索引**
- 每句话的偏移表存在**外部**，并且**按语言分别存**
- 换个包名，偏移表还是英文的，指向的位置全错

**教训**：这个游戏的资源是"索引表 + 裸数据堆"的分离设计，**换数据必须同时换索引**。
硬链接、改名、替换文件这类操作在这里全部无效。

**回滚**：删掉硬链接，恢复原文件。

---

## 阶段 3 — 转向资源层：解析 ISO 与索引表

**目标**：搞清楚 `DATA.TBL` + `DATA00.PAC` + `DATA01.PAC` 的结构。

**做法**：

1. 解析 XDVDFS：卷描述符在 `0xFD90000`，根目录在 `0xFDA0000`，文件偏移 = `sector × 2048`
2. 找到两个 PAC 在 ISO 中的位置（`0x06197F800` / `0x154E3A000`）
3. 解析 `DATA.TBL`：8 字节头 + 926 条 × 16 字节大端 `{flags, offset, comp_size, uncomp_size}`

**结果**：索引表结构很快搞清。条目按 `0x2000` 对齐，flags 的 bit24 决定 PAC 归属（`0` → DATA00，`1` → DATA01）。

**踩坑**：

- 一开始以为 `DATA.TBL` 的头部 8 字节里有两个有意义的值，实际只有第一个（记录数）有用
- Windows 上 Python 把 `/f/foo` 解释成 `C:\f\foo`，浪费了一轮调试。**路径一律写 `F:/foo` 或 `r"F:\foo"`**

---

## 阶段 4 — 破解压缩算法

**难点**：PAC 里的数据不是明文，也不是标准 zlib。

**试错过程**：

| 尝试 | 结果 |
|---|---|
| `zlib.decompress(data)` | 失败，`incorrect header check` |
| `zlib.decompress(data, -15)` | 失败，`invalid distance too far back` |
| 猜测 LZMA / LZ4 | 全部失败 |
| 观察：同一段数据不同记录，失败位置不同 | 说明有**按记录变化**的预处理 |

**突破**：发现预处理是 XOR，且垫值来自 **π 的十六进制小数**。

```
π = 3.243F6A88 85A308D3 13198A2E 03707344 ...
                ↑ 第 1、2 个 32 位字
```

对记录 `idx`：

```python
i = idx % 256
pad = pack(">II", W[2*i+1], W[2*i+2])   # 8 字节，循环平铺
comp = xor(raw, pad)
data = zlib.decompress(comp, -15)
```

**验证**：用这个算法解出第一条数据，长度与 `uncomp_size` 完全一致。之后 926 条全部通过。

**坑**：一开始用十进制 π 算，全错。必须是**十六进制展开**。

---

## 阶段 5 — FHM 容器与语言布局

**做法**：解压后的数据大多以 `FHM ` 开头。解析：

```
0x00 "FHM "
0x10 u32     子块数量
0x14 u32[n]  偏移表
0x14+4n u32[n] 尺寸表
```

写了递归遍历工具，把每个包的树打出来。

**发现**：过场包的结构里有一个"7 个子块、每个子块都是 FHM、每个子块的 chunk0 都是 CAPT"的容器 —— 这就是**语言容器**。

槽位顺序通过纹理尺寸判断：

- 中日文槽的 NTXR 是 `2048×256`（汉字多，需要大图集）
- 其他语言只有 `256×256`

→ `[0]` 日本語、`[1]` English（汉化后 = 中文）。

**设计决策**：写 `append_replace()` —— 不覆盖原字节，把新数据追加到容器末尾，只改偏移/尺寸表。
这样回滚只需要还原 `DATA.TBL`。

---

## 阶段 6 — 任务包迁移（成功）

**范围**：`#9` ~ `#23`，15 个任务包。

**做法**：

1. 字体：`chunk4`（日文字体）← `chunk5`（英文字体，汉化后含汉字字形）
2. 文本包：找到语言容器，把 `slot1`（中文）写进 `slot0`（日文）

**关键决策：以汉化包为基底**。

第一版用原版 ISO 的包当基底，只把中文槽塞进去 → **中文全丢**。
原因：汉化组不只改字幕槽，还改了字体、字号、排版。以原版为基底等于把它们全扔掉。

**结果**：用户实测**成功**。任务内对话字幕显示中文。

---

## 阶段 7 — CG 过场包（18 个，存疑）

**范围**：`#474, 477, 479, 482, 485, 487, 489, 493, 496, 498, 501, 503, 505, 507, 510, 515, 521, 529`
对应 `ed00_01` ~ `ed15_01`。

**做法**：和任务包一样，`slot0 ← slot1`，写入 `DATA01.PAC`。

**踩坑**：

- 初版脚本固定写 `DATA00.PAC`，实际这些包的 flags 是 `0x01010000`（属于 DATA01）→ 加了 `assert`
- 序列化时漏了 `c22/c23`，因为脚本只认 `nof == 4` 的包

**结果**：18/18 校验槽位一致。但**用户实测 CG 字幕仍是日文**。转折见阶段 11。

---

## 阶段 8 — 发现被漏掉的副本包

**触发**：用户反馈"有一个过场动画没有中文字幕"。

**排查**：全库扫描所有含 7 语言容器的包，发现 `#103 / #109 / #111 / #115 / #117` 的槽位**仍是日文**。

**验证方法**：拿原版 ISO 的对应包逐槽比对 md5。

```
#103 的 7 个槽 md5  ==  ISO #9 的 7 个槽 md5   （全等）
```

**结论**：这 5 个包是 `#9 / #15 / #17 / #21 / #23` 的**副本**，汉化组只改了正本、漏了副本。
游戏在部分场景读副本 → 显示日文。

**修复**：从正本取中文槽，写进副本的 `slot0` **和** `slot1`。

为什么两个都写：只写 `slot0` 时实测 `slot1` 仍是原版英文。虽然理论上只读 `slot0`，但不想依赖这个假设。

**结果**：用户反馈那一关的过场正常了。

---

## 阶段 9 — 全库审计

**方法升级**：不再"猜测哪里可能漏"，改成**以原版为基线做差集**。

1. 扫 ISO 原版，收集所有"日文字幕槽"的 md5（判据：NTXR ≥ 100 KB，即 CJK 大图集）
2. 扫当前库，凡是槽 md5 命中该集合的 → 仍是日文原样

**结果**：

```
语言容器总数：42
槽0 == 槽1：42
命中 ISO 日文槽：0
索引越界：0
```

**踩坑**：第一版审计脚本把"子块全是 FHM"当语言容器判据，导致顶层 26 / 55 个子块的**整个包**被误判，得出一堆假阳性。
判据必须收紧到：**每个子块的 chunk0 都是 CAPT**。

---

## 阶段 10 — 评估"改翻译"的可行性（结论：不可行）

用户问：汉化组有些翻译不好，能改吗？

**调查**：

1. 全库扫明文 —— UTF-8 / GBK / UTF-16LE / UTF-16BE，**0 命中**
2. 解析字幕块结构：
   ```
   语言块 FHM
   ├── CAPT      32 字节头
   ├── 排版表     47 × 16
   └── 图集 FHM  → NFH 字体名 + NTXR 纹理（DXT5）
   ```
3. 中日文图集 `2048×256` vs 其他语言 `256×256` → 汉字是**逐字烘进纹理**的

**结论**：字幕不是文本，是位图。改一句 = 重画字形 + 重编码 DXT5 + 处理 Xbox 360 tiled 布局。

**尝试解码纹理**：DXT5 解码出来是噪声。加了 32×32 tile 反变换 → 仍是噪声。说明还有一层 swizzle 没搞对，**暂时放弃**。

**决策**：这条线成本远超收益，终止。

## 阶段 11 — 开场 CG 仍日文 → 关键发现（未解决）

**现象**：用户说"出现汉化组图片之后就是开场 CG，还是日文"。

**逐条排除**：

| 假设 | 验证 | 结果 |
|---|---|---|
| 视频内嵌了字幕流 | 扫 ASF 对象的 `Script` / `Caption` / `Subtitle` | 全部 0 次，**无字幕流** |
| 汉化组替换了视频 | `moviepack.bin` 与原版 ISO 7 个采样点比对 | **全部 SAME**，没动过 |
| 字幕在音频包里 | 检查 `demopack_*.bin` / `bgmpack.bin` | XMA 音频，无关 |

**然后做了全库逐条对比**（当前 vs 原版 ISO，926 条）：

汉化组真正改过的条目：`#3`、`#9`~`#23`、`#170/171/177/178`、`#467`、`#500`、`#618`、`#683`、`#779`、`#878`~`#924`。

**`#474` ~ `#529` 的 18 个 CG 包，汉化组一个字节都没改。**

**进一步解析 CAPT**：

`#474` / `#477` / 以及任务包 `#9` 的 CAPT，排版表**全部为空**（0 条有效条目）。

**推论**：这些"语言容器"装载的是**字体/字形**，不是字幕文本。也就是说：

- 阶段 7 对 `#474`~`#529` 做的 `slot0 ← slot1`，**改的可能是字体而不是字幕**
- 用户看到 CG 字幕仍是日文，是因为**真正承载 CG 字幕的资源还没找到**
- 甚至有可能：汉化版**根本没有汉化 CG 字幕**，用户记忆中的"汉化过的 CG"其实是别的东西

**这件事到此为止，未解决。** 后续排查方向写在 [README §7](../README.md#7-尚未解决的问题)。

## 阶段 12 — 玩家实机验收（结论固化）

**验收人**：项目发起人（玩家视角，非脚本自检）

**结果**：

| 项目 | 结果 |
|---|---|
| 菜单 / UI | ✅ 中文 |
| 任务简报（briefing）字幕 | ✅ 中文 |
| 无线电字幕（radio） | ✅ 中文 |
| 任务内过场（第一关开场 + 结束） | ✅ 中文 |
| 开场 CG（汉化组 logo 之后那段，`ed00_01`） | ❌ **仍然是日文** |

**关键判断**：在**同一份补丁**下，`task` 相关的一切（简报、无线电、任务内过场）全部正常，唯独 CG 没变化。这不是"补丁没生效"，而是**CG 字幕不走这条资源路径**——`#474`~`#529` 的槽位复制对画面零影响，阶段 7 的操作被实测判定为无效。

**因此本项目的状态从"全部完成"修正为"任务内资源全部完成 + CG 字幕未解决"**，README §0 表格、`AGENT-HANDOFF.md` §3.3 与 §4 均按此结论更新。

**下一步优先级**：先做「原版 assets vs 汉化版 assets 播同一段 CG」的对比。如果原版也是日文，那就说明汉化组根本没做 CG 字幕，本项目的 CG 部分应当明确标注为"不在范围内"，而不是继续找资源。

## 附：失败尝试汇总（避免重复劳动）

| 尝试 | 为什么失败 |
|---|---|
| 只改 `ac6recomp.toml` 的 language | 文本和语音共用一个开关 |
| 硬链接 / 改名 voicepack | 音频无内部索引，偏移表按语言外置 |
| 用原版包做基底注入中文 | 丢掉汉化组的字体/排版改动 |
| 按 flags 单 PAC 读取 | 797 条解压错位，必须双试 + 长度校验 |
| 十进制 π 做 XOR 垫 | 必须用十六进制小数展开 |
| 只改正本不改副本 | 副本 `#103` 等 5 个包仍是日文 |
| 只写 `slot0` 不写 `slot1` | 实测 `slot1` 残留英文 |
| 每包硬编码 `nof == 4` | 漏掉 `c22/c23` 等结构不同的包 |
| 认为 `#467`~`#529` 全是字体 | 实际 `#474`~`#529` 是另一种结构 |
| 解 DXT5 纹理 | 缺一层 Xbox 360 swizzle，解不出字模 |
| 找 CG 字幕的明文 | 全库 0 命中，字幕是位图 |
